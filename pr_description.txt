🚨 Severity: HIGH
💡 Vulnerability: Potential Negative Caching DoS in Asset Proxy. When the proxy fetched upstream assets, it could theoretically cache failed responses (like 404 or 502) if the error throwing was removed to preserve HTTP semantics, causing CDNs to serve errors persistently. Additionally, throwing exceptions on upstream non-2xx responses bypassed the injection of security headers (like CSP and X-Content-Type-Options) for those specific error responses.
🎯 Impact: Attackers or random upstream failures could result in CDNs persistently caching a 5xx or 4xx error for 7 days (Negative Caching DoS). Furthermore, the lack of security headers on error pages reduced the overall defense-in-depth posture of the proxy.
🔧 Fix: Refactored `handleAssets` to pass through upstream non-OK responses directly to preserve standard HTTP semantics securely without throwing exceptions. Conditionally applied `Cache-Control: public, max-age=604800` only to successful (`response.ok`) responses, and applied `Cache-Control: no-store, no-cache, must-revalidate` to error responses. Ensured `SECURITY_HEADERS` are applied to both success and failure paths.
✅ Verification: Ran `node -c src/assets.js` to verify syntax. Code review confirmed the fix is correct and prevents caching of error responses while maintaining security headers.
