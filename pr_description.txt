🚨 Severity: HIGH

💡 Vulnerability: The application previously configured the `Access-Control-Allow-Origin` header to `*` for the entire dashboard proxy and security context.

🎯 Impact: A wildcard CORS policy disables the Same-Origin Policy. If sensitive endpoints or proxy actions rely on cookies or specific local environments, this could allow a malicious site to make cross-origin requests to this domain on behalf of a victim, potentially leading to unauthorized data access or SSRF-like behavior depending on the specific proxy target.

🔧 Fix: Removed `Access-Control-Allow-Origin: '*'` from `STATIC_SECURITY_HEADERS` and `SECURITY_HEADERS` in `src/security.js` and removed the explicit override in `src/assets.js`, enforcing standard Same-Origin behavior by default unless explicitly needed. (Since telemetry points already omit this header as a 1x1 pixel image).

✅ Verification: Run `node -c src/index.js` and `node -c src/security.js`. Checked that tests pass and the security headers no longer inject a wildcard CORS origin.
